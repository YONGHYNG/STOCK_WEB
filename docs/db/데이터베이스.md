# 데이터베이스 구조

## 1. 기본 정보

- DBMS: SQLite
- 파일: `data/trading.db`
- 연결 구현: `backend/database.py`
- 저널 모드: `WAL`
- 동기화: `NORMAL`
- 캐시: 약 32 MiB (`PRAGMA cache_size=-32000`)
- 외래 키: 현재 정의 없음
- 테이블 수: 7개

서버 시작 시 `init_db()`가 없는 테이블과 컬럼을 생성한다. 별도의 스키마 버전 테이블이나 Alembic 마이그레이션은 없고, `ALTER TABLE`을 코드에서 순차 실행하는 방식이다.

## 2. 테이블 요약

| 테이블 | 용도 | 기본 키 |
|---|---|---|
| `candles` | 시간봉 OHLCV 저장 | `symbol`, `timeframe`, `timestamp` 복합 키 |
| `signals` | 확정봉별 분석 신호와 진단 결과 | `id` |
| `trades` | PAPER·LIVE·PLAN 거래 기록 | `id` |
| `live_execution_state` | 미체결 또는 체결 확인 중인 실주문 복구 상태 | `symbol` |
| `live_risk_state` | 실거래 긴급정지 상태 | `id=1` |
| `scheduled_entry_sessions` | 날짜별 고정 진입 세션 처리 상태 | `session_date`, `session_key` 복합 키 |
| `paper_account` | 모의계좌 라운드와 잔액 | `id=1` |

SQLite의 `INTEGER PRIMARY KEY`는 행 식별자 역할을 하며, `signals.id`와 `trades.id`는 자동 증가한다.

## 3. `candles`

시장 분석에 사용하는 BTCUSDT OHLCV 시간봉이다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `symbol` | TEXT | 예 | - | 거래 심볼, 현재 `BTCUSDT` |
| `timeframe` | TEXT | 예 | - | `1m`, `5m`, `15m`, `30m`, `1H`, `4H`, `6H`, `1D` 등 |
| `timestamp` | INTEGER | 예 | - | 캔들 시작 시각 Unix 밀리초 |
| `open` | REAL | 예 | - | 시가 |
| `high` | REAL | 예 | - | 고가 |
| `low` | REAL | 예 | - | 저가 |
| `close` | REAL | 예 | - | 종가 |
| `volume` | REAL | 예 | - | 거래량 |

인덱스:

- 기본 키: `(symbol, timeframe, timestamp)`
- `idx_candles_lookup`: `(symbol, timeframe, timestamp DESC)` 조회 가속

## 4. `signals`

동일한 심볼·시간봉·확정봉에는 하나의 최신 분석 결과만 보존한다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | INTEGER | PK | 자동 증가 | 신호 번호 |
| `symbol` | TEXT | 예 | - | 거래 심볼 |
| `timeframe` | TEXT | 예 | - | 신호 기준 시간봉 |
| `timestamp` | INTEGER | 예 | - | 확정봉 Unix 밀리초 |
| `entry_price` | REAL | 아니요 | NULL | 계획 진입가 |
| `direction` | TEXT | 아니요 | NULL | `LONG`, `SHORT`, `HOLD` 등 |
| `long_probability` | REAL | 아니요 | NULL | LONG 확률·점수 |
| `short_probability` | REAL | 아니요 | NULL | SHORT 확률·점수 |
| `confidence` | REAL | 아니요 | NULL | 종합 신뢰도 |
| `stop_loss` | REAL | 아니요 | NULL | 계획 손절가 |
| `take_profit_1` | REAL | 아니요 | NULL | 1차 익절가 |
| `take_profit_2` | REAL | 아니요 | NULL | 2차 참고 익절가 |
| `risk_reward_ratio` | REAL | 아니요 | NULL | 계획 손익비 |
| `all_time_high_mode` | INTEGER | 아니요 | `0` | 신고가 모드 여부, 0/1 |
| `all_time_low_mode` | INTEGER | 아니요 | `0` | 신저가 모드 여부, 0/1 |
| `reason` | TEXT | 아니요 | NULL | 신호 설명 |
| `created_at` | DATETIME | 아니요 | 현재 시각 | 생성 시각 |
| `market_regime` | TEXT | 아니요 | NULL | 장세 분류 |
| `strategy_signal` | TEXT | 아니요 | NULL | 세부 전략 신호명 |
| `entry_grade` | TEXT | 아니요 | NULL | A, B 등 진입 등급 |
| `diagnostics_json` | TEXT | 아니요 | NULL | 지표와 진단값 JSON 문자열 |
| `block_reason` | TEXT | 아니요 | NULL | 진입 차단 사유 |

인덱스:

- `idx_signals_unique_bar` UNIQUE: `(symbol, timeframe, timestamp)`

## 5. `trades`

모의매매, 실거래, 분석용 계획을 함께 기록한다. `trade_type`으로 구분한다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | INTEGER | PK | 자동 증가 | 거래 번호 |
| `symbol` | TEXT | 예 | - | 거래 심볼 |
| `direction` | TEXT | 예 | - | `LONG` 또는 `SHORT` |
| `entry_price` | REAL | 예 | - | 현재 평균 진입가 |
| `stop_loss` | REAL | 아니요 | NULL | 활성 손절가 |
| `take_profit_1` | REAL | 아니요 | NULL | 활성 1차 익절가 |
| `take_profit_2` | REAL | 아니요 | NULL | 2차 참고 익절가 |
| `risk_reward` | REAL | 아니요 | NULL | 손익비 |
| `confidence` | REAL | 아니요 | NULL | 진입 신뢰도 |
| `long_prob` | REAL | 아니요 | NULL | LONG 점수 |
| `short_prob` | REAL | 아니요 | NULL | SHORT 점수 |
| `tf_directions` | TEXT | 아니요 | NULL | 시간봉별 방향 JSON |
| `entry_reason` | TEXT | 아니요 | NULL | 진입 이유 |
| `entry_time` | DATETIME | 아니요 | 현재 시각 | 최초 진입 시각 |
| `exit_price` | REAL | 아니요 | NULL | 최종 청산가 |
| `exit_time` | DATETIME | 아니요 | NULL | 최종 청산 시각 |
| `result` | TEXT | 아니요 | `OPEN` | `OPEN`, `TP1`, `SL`, `TIME_EXIT` 등 |
| `pnl_pct` | REAL | 아니요 | NULL | 최종 손익률 |
| `profit_reason` | TEXT | 아니요 | NULL | 이익 청산 설명 |
| `loss_reason` | TEXT | 아니요 | NULL | 손실 청산 설명 |
| `notes` | TEXT | 아니요 | NULL | 추가 메모 |
| `trade_type` | TEXT | 예 | `LIVE` | `PAPER`, `LIVE`, `PLAN` |
| `realized_pnl_amount` | REAL | 아니요 | NULL | 최종 실현손익 금액 |
| `size_btc` | REAL | 아니요 | NULL | 현재 또는 최종 BTC 수량 |
| `entry_order_id` | TEXT | 아니요 | NULL | 거래소 진입 주문 ID |
| `exchange_position_id` | TEXT | 아니요 | NULL | 거래소 포지션 식별자 |
| `entry_fee` | REAL | 아니요 | NULL | 진입 수수료 |
| `exit_fee` | REAL | 아니요 | NULL | 청산 수수료 |
| `funding_fee` | REAL | 아니요 | NULL | 펀딩비 |
| `net_profit` | REAL | 아니요 | NULL | 수수료·펀딩비 반영 순손익 |
| `synced_at` | DATETIME | 아니요 | NULL | 거래소 동기화 시각 |
| `position_size_percent` | REAL | 예 | `100` | 계획 대비 현재 진입 비중 |
| `entry_stage` | INTEGER | 예 | `2` | 현재 진입 단계 |
| `initial_size_btc` | REAL | 아니요 | NULL | 최초 진입 BTC 수량 |

## 6. `live_execution_state`

프로그램 재시작 후에도 진행 중인 실주문을 복구하기 위한 단일 심볼 상태다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `symbol` | TEXT | PK | - | 거래 심볼 |
| `order_id` | TEXT | 아니요 | NULL | 거래소 주문 ID |
| `client_oid` | TEXT | 아니요 | NULL | 클라이언트 주문 ID |
| `direction` | TEXT | 예 | - | 주문 방향 |
| `planned_entry` | REAL | 예 | - | 계획 진입가 |
| `stop_loss` | REAL | 예 | - | 계획 손절가 |
| `take_profit` | REAL | 예 | - | 계획 익절가 |
| `order_created_ms` | INTEGER | 예 | - | 주문 생성 Unix 밀리초 |
| `position_ctime` | TEXT | 아니요 | NULL | 거래소 포지션 생성 시각 |
| `status` | TEXT | 예 | `PENDING` | 실행 상태 |
| `updated_at` | DATETIME | 아니요 | 현재 시각 | 갱신 시각 |

## 7. `live_risk_state`

실거래 긴급정지를 재시작 후에도 유지한다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | INTEGER | PK | - | 항상 `1` |
| `emergency_stopped` | INTEGER | 예 | `0` | 긴급정지 여부, 0/1 |
| `reason` | TEXT | 아니요 | NULL | 정지 사유 |
| `updated_at` | DATETIME | 아니요 | 현재 시각 | 갱신 시각 |

## 8. `scheduled_entry_sessions`

같은 날짜의 같은 고정 세션이 중복 실행되지 않도록 처리 결과를 저장한다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `session_date` | TEXT | PK | - | 세션 날짜 |
| `session_key` | TEXT | PK | - | 세션 이름·키 |
| `status` | TEXT | 예 | - | `PENDING`, `ENTERED`, `SAFETY_BLOCKED` 등 |
| `mode` | TEXT | 아니요 | NULL | PAPER 또는 LIVE 모드 |
| `direction` | TEXT | 아니요 | NULL | LONG 또는 SHORT |
| `detail` | TEXT | 아니요 | NULL | 처리 내용 |
| `processed_at` | DATETIME | 아니요 | 현재 시각 | 처리 시각 |

## 9. `paper_account`

모의계좌는 거래 기록을 삭제하지 않고 `reset_after_trade_id` 이후 거래만 현재 라운드 손익으로 계산한다.

| 컬럼 | 형식 | 필수 | 기본값 | 설명 |
|---|---|---:|---|---|
| `id` | INTEGER | PK | - | 항상 `1` |
| `initial_balance` | REAL | 예 | - | 라운드 초기 잔액 |
| `balance` | REAL | 예 | - | 확정 손익 반영 잔액 |
| `leverage` | REAL | 예 | - | 모의계좌 레버리지 |
| `updated_at` | DATETIME | 아니요 | 현재 시각 | 잔액 계산 시각 |
| `reset_after_trade_id` | INTEGER | 예 | `0` | 이 ID 이후 PAPER 거래만 현재 라운드에 반영 |
| `round_name` | TEXT | 예 | 빈 문자열 | 라운드 표시 이름 |

`reconcile_paper_account()`는 현재 라운드의 청산 거래를 ID 순서로 다시 계산해 `balance`와 누락된 `realized_pnl_amount`를 갱신한다.

## 10. 재시작과 데이터 보존

프로그램을 껐다 켜도 다음 정보는 DB에 남는다.

- 캔들, 신호, 거래 이력
- 모의계좌 잔액과 라운드 기준점
- 실거래 긴급정지 상태
- 진행 중인 실주문 복구 상태
- 처리 완료한 고정 진입 세션

반대로 화면 로그 버퍼, 마지막 분석 객체와 일부 대기 상태는 메모리 상태이므로 재시작 시 다시 구성된다. DB 파일을 직접 수정하기 전에는 서버를 중지하고 SQLite 백업 API 또는 안전한 백업 도구를 사용하는 것이 좋다. WAL 사용 중에는 `trading.db` 파일 하나만 단순 복사하면 최신 WAL 내용이 빠질 수 있다.
